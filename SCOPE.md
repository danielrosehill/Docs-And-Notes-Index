# Scope — Docs And Notes Index

## What belongs here

Repositories whose purpose is to **publish documentation, notes, guides, or reference material** — content intended to be read, often surfaced via the docs website (`docs.bydanielrosehill.com`).

Include a repo if it is:

- A collection of how-to guides, tutorials, or walkthroughs
- Personal notes or knowledge base entries on a topic
- Reference material (cheatsheets, glossaries, link collections)
- Write-ups of troubleshooting, debugging, or fixes
- Published documentation tied to the docs site

The defining test: **the repo's value is the prose, and the prose is meant to be read by others (or future-Daniel) as reference.**

## What does NOT belong here

- **Plans or specs for projects to be built** → use `Architectural-Plans-Index`
- **Work-in-progress code projects** → use `WIP-Index`
- **Ideation / brainstorming repos** → `Architectural-Plans-Index`
- **Curated link lists that function as indices of other repos** → those are themselves indices, list in `Index-Of-Indices`

## Overlap rules

- A docs repo can appear in a topical index alongside this one (e.g. an AI docs repo may also live in `AI-Projects-Index`)
- Prefer this index when the repo is purely documentation with no associated code project
- If a repo contains docs *about* a separate code project, index the code project in its topical index and the docs here only if substantial enough to stand alone
